# 卡片設計美學知識庫 (Cardbook)

本文件是 **CardGen** 卡片生成系統的核心美學知識庫，為 AI 圖片生成與網頁前端渲染提供設計依據。

文件涵蓋三大面向：
1. **美學分類分析** — 各類型卡片的構圖、字體、主圖片視覺與色調的深度拆解
2. **設計技能體系** — 從資訊架構到互動工程的完整技能樹與實踐引導
3. **規格對照附錄** — 實體尺寸與數位解析度的快速查表

## 1. 美學分類深度分析

### 1.1 遊戲與蒐藏類（TCG / IP / 運動卡）

這類卡片是視覺張力與資訊承載的極致結合，設計核心在於「營造儀式感與稀有度」。

* **魔法風雲會（MTG） & 遊戲王：**
  * **構圖設計：** 採用經典的「上圖下文」三分法構圖（頂部標題、中部插畫、底部效果說明）。遊戲王更強調插畫框的「出框感」（特寫角色突破邊框），營造立體張力。
  * **字體選用：** MTG 使用襯線體（如 *Beleren* 改良體），傳遞奇幻、歷史沉澱感；遊戲王則在日文/中文版使用粗獷的毛筆或裝飾性黑體，強調戰鬥的力道。
  * **主圖片視覺：** 高精細度的奇幻插畫、怪物特寫、或是帶有故事背景的場景。
  * **色調規劃：** 嚴格的屬性色彩編碼。例如 MTG 的「白藍黑紅綠」五色魔法力，底色與外框色調必須與卡片屬性高度一致，以便玩家在 0.5 秒內辨識。

* **寶可夢卡牌（PTCG）：**
  * **構圖設計：** 現代 PTCG 經常打破邊框限制，採用「滿版插畫（Full Art）」構圖。資訊（HP、技能）直接疊加在主圖片之上。
  * **字體選用：** 使用易讀性極高、筆劃中規中矩的無襯線體（如 *Gill Sans* 或圓體），確保兒童閱讀不費力。
  * **主圖片視覺：** 精靈寶可夢的動態角色插畫，配合強烈的透視線與放射狀背景。
  * **色調規劃：** 極飽和、鮮明的高彩度色調（如電系的鮮黃、火系的亮紅、草系的翠綠），搭配閃卡特有的雷射折射光澤（Holographic）。

* **運動卡（棒球卡、籃球卡）：**
  * **構圖設計：** 正面為非對稱的「動態肖像」構圖，背部則是密集的「表格化柵格（Grid）」構圖。
  * **字體選用：** 正面使用具備運動感、傾斜且粗重的無襯線體（如 *Impact* 或強烈裝飾線字體）；背面則使用極度壓縮的等寬字體（Monospace），確保海量數據對齊。
  * **主圖片視覺：** 球員在賽場上的高畫質瞬間捕捉、擊球或灌籃的張力動作。
  * **色調規劃：** 通常以球隊代表色為主色調，輔以金屬銀、土豪金等象徵榮譽的點綴色。

* **貪婪之島卡片：**
  * **構圖設計：** 邊界感極強的「卡牌框架（Frame）」。卡片上方放置卡牌編號與入手難易度，中央為魔法效果圖，下方為詳細咒語說明。
  * **字體選用：** 神祕感十足的襯線體或歌德體，搭配帶有魔法風味的符號系統。
  * **主圖片視覺：** 偏向古典、寫實且帶有超現實風格的魔法物品或儀式插畫。
  * **色調規劃：** 以泛黃的羊皮紙色（Parchment）為基調，搭配低飽和度的暗金色、深藍色與磚紅色，營造歷史與神祕規則感。

本系統採用 **「主圖生成 -> 自動裁切 -> HTML/CSS 模板渲染 -> 瀏覽器截圖」** 的現代化數位卡片生產線：

1. **主圖與框架分離原則：** AI 僅生成 1024x1024 的無邊框、無文字純主視覺 (Key Visual)。所有的卡面資訊（卡名、數值、屬性、說明文字、邊框、裝飾花紋）皆由 HTML/CSS 負責渲染，以確保文字清晰度與隨時修改的彈性。
2. **置中安全區域（Safe Zone）：** 由於 AI 生成的 1024x1024 圖片後續需要進行裁切，在設計 Image Prompt 時必須指定「主體置中」，將核心元素保留在中央 80% 區域內，避免裁切時損害主體。
3. **色彩空間與格式：** 數位卡片採用 sRGB 色彩空間，避免在 Prompt 使用印刷專用的 CMYK 或 Pantone 詞彙。輸出格式一律為無損 PNG 格式。

**Prompt 結構公式：**
```

```

**各段落關鍵字範例：**

| 段落 | 用途 | 關鍵字範例 |
|------|------|-----------|
| 美學風格 | 定義卡牌流派 | `PTCG style illustration`, `classic TCG Yu-Gi-Oh style`, `luxurious gold relief` |
| 主體描述 | 描述角色或物品 | `a fierce dragon engulfed in blue lightning`, `a divine goddess wearing golden armor` |

| 陷阱 | 現象 | 解法 |

| 生成卡片邊框 | AI 自行加入邊框與 UI 元素 | 加入 `illustration only, no card frame, no border, no UI elements` |

## 2. 卡片設計技能樹

將美學元素與結構邏輯融為一體的實作指南，共四大技能分支：

### 2.1 資訊架構與構圖規劃 (Information Architecture & Composition)

- **黃金比例與微型網格（Micro-grid systems）** — 以 8px 為基礎單位建立間距系統，確保所有元件的 Padding 與 Margin 為 8 的倍數，保證任意縮放下比例與節奏感一致。
- **角落資訊佈局（Corner-oriented UX）** — 將關鍵資訊（如 HP、屬性符號）配置於四角，確保在扇形持牌或縮圖瀏覽時仍可辨識。
- **資訊優先級與視覺流向（Eye-tracking Z-pattern）** — 利用 Z 字型或 F 字型視覺動線，引導讀者從標題 → 主圖 → 效果文字依序閱讀。

### 2.2 字體系統與易讀性 (Typography & Readability)

- **襯線體、無襯線體、等寬字體的使用場景** — 襯線體用於奇幻或歷史感；無襯線體用於現代與休閒；等寬字體用於數值對齊與數據密集區域。
- **數位螢幕的像素級字體優化（Line-height & Letter-spacing）** — 卡片標題建議 `line-height: 1.1`，描述文字建議 `line-height: 1.4 ~ 1.6`，避免行距過鬆或過緊。
- **字重對比（Font weight hierarchy）** — 標題使用 700~900 (Bold/Black)，副標使用 500~600 (Medium/SemiBold)，內文使用 400 (Regular)，形成清晰的層級。

### 2.3 主圖片視覺與色調工藝 (Key Visual & Color Craft)

- **角色/物品的「出框」視覺震撼力（3D depth creation）** — 讓主體角色的肢體或武器突破卡片邊框，在 Prompt 中使用 `pop-out 3D effect, breaking frame` 等描述。
- **系統化色彩編碼（Color-coding system）** — 為不同屬性/類別建立嚴格的色彩對應（火=紅、水=藍、草=綠），確保玩家 0.5 秒內辨識卡片屬性。
- **實體印刷工藝與數位擬物化** — 實體：燙金、雷射折射、霧面處理；數位：使用 CSS `background-blend-mode`、`filter` 與漸層動畫模擬印刷光澤。

### 2.4 系統化與互動工程 (Design System & Interactivity)

- **響應式卡片變體與自動佈局** — 同一張卡片應具備至少三種尺寸變體（縮圖 120px、標準 300px、展示 600px），使用 CSS Container Queries 或比例計算自動適配。
- **數位卡片的動態過渡（Flip, Hover, Drag transitions）** — 翻轉效果使用 `transform: rotateY(180deg)`，懸停使用 `scale(1.05)` + `box-shadow` 提升，拖曳使用 `pointer events` 搭配物理慣性動畫。
- **無障礙色彩對比度規範（WCAG 2.1 AA/AAA）** — 背景與文字對比度至少達 4.5:1 (AA)，大標題至少達 3:1，確保色覺障礙使用者也能辨識。

## 3. 實踐引導

### 3.1 構圖與字體實踐

1. **構圖實踐：** 設計數位卡片時，先建立 8px 的微型網格系統。所有間距（Padding）與元件邊界（Margin）都必須是 8 的倍數。這能保證不論卡片尺寸如何縮放，內部的比例與節奏感依然嚴謹。
2. **字體與色調實踐：** 避免在卡片上使用超過兩種字型。標題使用粗壯的無襯線體（如 *Inter Bold*）來抓住視線，數值與標籤則使用等寬字體（如 *JetBrains Mono*）確保數值變動時卡片寬度不會抖動。背景與主要文字的色彩對比度必須至少達到 4.5:1，以符合無障礙設計的基本要求。

### 3.2 數位卡片設計指引

本系統的卡片圖片由 AI 生成後，在網頁前端以 CSS 渲染邊框、標題字與數值，因此設計時需注意以下原則：

1. **主圖與框架分離原則：** AI 生成的圖片僅為「卡面主圖 (Key Visual)」，不應包含邊框、標題文字或數值按鈕。這些 UI 元素由前端 CSS 負責渲染，以確保一致性與可維護性。
2. **色彩空間：** 數位卡片使用 sRGB 色彩空間。在 Image Prompt 中避免指定 CMYK 印刷色彩描述，以免 AI 生成偏暗或失真的色調。
3. **安全區域（Safe Zone）：** 主圖的核心內容應集中在中央 80% 區域，避免關鍵視覺元素被前端邊框或圓角裁切。
4. **透明與出血：** 若設計「出框感」卡片，主體角色可延伸至圖片邊緣，但需確保背景區域能被前端框架自然融合。
5. **檔案格式：** 統一使用 PNG 格式（無損壓縮），確保透明度與細節完整保留。

### 3.3 Image Prompt 工程指南

設計 AI 生成卡片圖片的 Prompt 時，依照以下結構組合關鍵字：

**Prompt 結構公式：**
```

```

**各段落關鍵字範例：**

| 段落 | 用途 | 關鍵字範例 |
|------|------|-----------|
| 美學風格 | 定義卡片類型 | `PTCG style illustration`, `classic TCG Yu-Gi-Oh style`, `luxurious gold relief` |
| 主體描述 | 描述角色或物品 | `a fierce dragon engulfed in blue lightning`, `a divine goddess wearing golden armor` |
| 動態與構圖 | 控制視角與張力 | `dynamic perspective action pose`, `pop-out 3D effect, breaking frame`, `symmetrical centered composition` |
| 色調與光影 | 控制氛圍 | `vivid holographic reflection overlay`, `dark cosmic deep blue background`, `warm pastel color palette` |
