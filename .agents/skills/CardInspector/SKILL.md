# CardInspector（卡片品質稽核專家）

## 任務目標

擔任卡片合成流程中的**品質審查關卡 (Quality Gate)**。在生成卡片截圖後，必須執行自動化與視覺品質檢查，確保卡面排版中角色主體完整，且排版完全符合美學規範。

---

## 核心品質關卡 (Quality Gates)

在檢查卡片時，必須依序執行以下 5 個品質關卡：

### G1. 主圖裁切完整性 (Main Image Crop Integrity)
* **檢測點**：比對置中裁切後的原圖 (`_cropped.png`) 與最終合成卡片 (`_card.png`) 中的主圖展示區。
* **主要風險**：TCG 模板的 `.card-image` 容器多為橫式長寬比（如 `702x520px`），如果使用預設的 `object-fit: cover` 且對齊方式為 `center`，會將直式插畫的頂部（角色頭部、耳朵、帽子、武器）與底部嚴重切除。
* **合格標準**：角色的面部、頭頂、耳朵、帽子或手持武器的頂端等「標誌性特徵」必須完整保留，不得被卡牌邊框或效果欄二次裁切。
* **修正策略**：
  * 在 HTML 模板中引入動態 `--img-position` CSS 控制。
  * 若角色頭部被切，在資料庫的卡片屬性中加入 `圖片對齊`（如 `top` 或 `50% 10%`），使主圖向上偏置，保留頭部細節。

### G2. 截圖尺寸規範 (Screenshot Resolution)
* **檢測點**：合成卡片 PNG 檔案的真實解析度。
* **合格標準**：
  * **直式卡片 (TCG, PTCG, Sports, GreedIsland, Poker)**：寬度必須正好為 `750px`，高度正好為 `1050px` (±5px 容差)。
  * **橫式卡牌 (CreditCard)**：寬度必須正好為 `1011px`，高度正好為 `638px`。
* **修正策略**：在 Playwright 截圖時強制設定 `deviceScaleFactor: 1`，並指定對應的 viewport 大小。

### G3. 元素溢出與 JS 錯誤 (Layout Overflow & Console Errors)
* **檢測點**：瀏覽器控制台輸出與 CSS 溢出狀態。
* **合格標準**：
  * 頁面載入時 JS Console 無任何拋錯。
  * 卡名、效果文字、屬性數值不得超出其預設的 CSS container 邊界，亦不得發生重疊。
* **修正策略**：調整字型大小（`font-size`）、設定行高（`line-height`）或使用彈性寬度。

### G4. 資料一致性 (Data Matching)
* **檢測點**：合成卡面上的文字內容與 `CBD.md` 資料庫的比對。
* **合格標準**：卡片名稱、ID、星級、屬性、ATK/DEF、技能名稱、技能傷害與效果文字等，必須與資料庫內記錄的內容完全一致。
* **修正策略**：修改 HTML 模板載入參數或更新 `CBD.md` 屬性。

### G5. 視覺完整性 (Visual Completeness)
* **檢測點**：卡片各視覺層（背景、外框、特效、裝飾元件）是否均加載完成。
* **合格標準**：卡片不應出現損壞的圖片占位符、斷裂的字型、或是缺失的圓角外框。
* **修正策略**：確認相關 local resources 或外部網頁字型是否完全加載後才進行 Playwright 截圖。

---

## 執行流程

1. **取得卡片規格與圖片路徑**。
2. **運行檢測腳本**，產出關卡檢測報告。
3. **若 G1 失敗（角色頭部被切）**：
   - 評估並計算所需偏置（例如將 `object-position` 調整為 `50% 10%`）。
   - 在 `CBD.md` 卡片屬性中登錄該偏置。
   - 重新運行合成截圖腳本，將偏置參數帶入模板。
4. **重新驗證**直到 5 關全數通過。
