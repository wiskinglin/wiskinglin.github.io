# PocketMoney 全產品地毯式找碴與自動化驗收測試計畫書 (QA_TEST_PLAN.md)

> **本文件是 PocketMoney 產品驗收之最高品質標準與自動化回歸測試準則。**
> 任何功能合併至主力程式 `pocketmoney.html` 前，必須由獨立的 **QA Inspector** 依據本測試計畫書逐項執行嚴格檢驗，不得省略任何維度。

---

## 1. 測試目標與哲學

1. **Adversarial Mindset (找碴哲學)**：
   - 測試的目標不是「證明程式可以跑」，而是「以最刁鑽、最嚴苛的使用者角度，把潛藏的視覺破版、互動失效、計算矛盾、狀態殘留全部挖出來」。
2. **多模態全頁視覺守門 (Vision QA)**：
   - 杜絕僅靠程式碼靜態檢查或首屏截圖。必須使用 Playwright 截取全頁長截圖 (`full_page=True`)，覆蓋自頁首至頁尾，並透過視覺辨識逐張檢查渲染完整性。
3. **零容忍原則 (Zero-Tolerance Gate)**：
   - 0 JS Error / 0 Unhandled Rejection
   - 0 `NaN`、`undefined`、`null`、`Infinity%`、`-0` 或異常負數小數
   - 0 跨分頁數據矛盾
   - 0 DOM 外漏與全螢幕滿版破格
   - 100% 符合 `UI_VOCABULARY.md` 與 `UXD.md` 零 AI Slop 鐵律（無版本標籤、無內部黑話、無教學式副標）
   - 100% 符合 ADR-017 瀏覽（100% 純 Insight）與輸入（專用流程）徹底分離架構

## 2. 六大維度地毯式測試矩陣

### 維度 1：8 大分頁逐頁切換與 DOM 隔離檢查 (Tab Navigation & DOM Leak Audit)
- **測試目標**：確保 8 大核心分頁互相獨立，切換分頁時絕對不發生元件外漏、樣式破裂或標題狀態覆蓋。
- **涵蓋分頁**：
  1. `總覽 (tab-dashboard)`
  2. `銀行餘額 (tab-banks)`
  3. `台股部位 (tab-stocks)`
  4. `信用卡費 (tab-cards)`
  5. `分期付款 (tab-installments)`
  6. `固定費用 (tab-bills)`
  7. `收支規則 (tab-rules)`
  8. `設定 (tab-settings)`
- **檢驗項目與斷言準則**：
  - [ ] **DOM 隔離檢驗**：非當前作用中分頁（包含 `.hidden` 類別）其下任何卡片或圖表容器，其 `offsetParent` 必須為 `null`，且絕對不得渲染在當前可見畫面上。
  - [ ] **全頁長截圖審查**：切換至每一分頁皆需截取 `full_page=True` 圖片，檢查頁面最下方是否漏出其他分頁（如圖表漏在總覽底部、脫離 `<main>` 容器寬度變全螢幕）。
  - [ ] **頂部大標題一致性**：在切換各分頁（如切換至 `台股部位`、`設定`）後再點回 `總覽`，頂部大標題與 `<title>` 必須保持為規範字串，嚴禁被覆蓋為殘留字串或空白。
  - [ ] **純唯讀洞察驗證**：檢查瀏覽分頁中嚴禁存在原地破壞性修改按鈕（如原地平帳、手動扣款、換月重置等）。

### 維度 2：4 種資料生命周期狀態切換 (Data Lifecycle Audit)
- **測試目標**：驗證系統在無資料、載入示範資料、切換官方情境、以及完全清空後的所有狀態表現。
- **涵蓋狀態**：
  1. **狀態 A：初次開箱純淨 0 資料 (Empty State)**
     - 檢查項目：所有 8 個分頁無任何 `NaN`、`undefined`、`null`、`Infinity%`、`-0`。
     - Chart.js 刻度防呆：Y 軸座標絕對不得出現 `-0.2, -0.4, -0.8, -1` 等負數小數刻度。
     - 警報防呆：常態收入與支出為 0 時，嚴禁跳出「入不敷出赤字紅字警告」或「餘額不足」紅字。
     - 空狀態友善引導：各分頁優雅顯示「尚無帳戶/資料」提示與引導。
  2. **狀態 B：展示沙盒切換 (Profile Demo Sandbox)**
     - 檢查項目：透過頂部帳本切換器切換至示範帳本，所有 8 個分頁之數值、卡片與趨勢圖表必須即時重繪 (Re-render)，各分頁數據完整且無須重新整理。
  3. **狀態 C：相容性情境資料庫切換 (Official Scenarios DB)**
     - 依序匯入 3 份官方情境資料庫：
       - `pocketmoney/database/scenario_1_junior_installments.json`（初級大人・分期生活族）
       - `pocketmoney/database/scenario_2_sandwich_mortgage.json`（少子化勇者・三明治雙薪房貸族）
       - `pocketmoney/database/scenario_3_stock_investor.json`（高級大人・存股領息置產族）
     - 檢查項目：歷史卡費 `records` 跨月份相容性、分期總期數與剩餘期數自動推算、固定費用頻率（雙月/單月）、股票損益計算等，絕無卡費歸零或趨勢圖破裂。
  4. **狀態 D：完全清空重設 (Factory Reset)**
     - 檢查項目：於設定頁執行「完全清空重設」後，系統必須 100% 恢復至狀態 A 純淨狀態。
     - 殘留檢驗：圖表線條歸零、導覽列待辦紅點數字徽章（`badgeBanks`, `badgeCards`, `badgeBills`）即時清空/隱藏、無殘留篩選或選取狀態。

### 維度 3：時間控制器與微觀/宏觀視角檢驗 (Temporal Controller Audit)
- **測試目標**：對齊 ADR-017，驗證微觀單月控制器僅存在於總覽頁，其他瀏覽分頁為 12 個月宏觀洞察；驗證歷史、當前與未來月份的動態計算準確度。
- **檢驗項目與斷言準則**：
  - [ ] **時間軸控制器專屬性**：單月時間切換器（`< 前月 | YYYY/MM | 次月 >` 及「回到今天」）僅在「總覽」分頁顯示，其餘分頁不設單月切換器，保持 12 個月趨勢圖與宏觀洞察。
  - [ ] **總覽單月切換響應**：
    - 連續點擊 `前月 (<)`、`次月 (>)`、指定月份與「回到今天」，總覽頁 KPI 與月度現金流即時重算。
    - **過去歷史月份**：若卡費已結清，待繳顯示為 0，且自動隱藏當月即時扣款防禦檢核（歷史已成定局，不發出已過期警報）。
    - **當前月份**：完整呈現單月現金流餘裕、各銀行扣款安全紅綠燈與大額雷達。
    - **未來月份**：依據分期合約 (`installments` 依起算年月推算) 及固定費用 (`bills` 雙月奇偶排程) 動態推估未來流量，無靜態捏造數據。
  - [ ] **12 個月趨勢圖區間切換**：
    - 在「銀行餘額」、「信用卡費」、「分期付款」、「固定費用」分頁，測試「近 12 個月」與「當年度」區間切換，圖表與指標即時重繪且無閃爍或刻度跑版。

### 維度 4：兩階段盤點輸入與純唯讀視圖檢驗 (Input Flow & Read-Only Audit)
- **測試目標**：驗證 ADR-017「輸入專用流程」與「瀏覽純洞察」之徹底分離，以及 ADR-014 廢棄跨行調撥之貫徹。
- **檢驗項目**：
  1. **兩階段每月盤點輸入抽屜 (Monthly Check-in Flow)**：
     - 點擊頂部 `[+ 每月盤點輸入]` 展開專用抽屜。
     - **階段一（信用卡帳單）**：輸入各卡當期應繳金額，支援翻面記錄 `> $5,000` 單筆大額消費；支援對帳單分析器 JSON 增量匯入。
     - **階段二（銀行帳戶盤點）**：展示各帳戶最新結餘與理論滾算預估餘額，支援一鍵確認或手動修正實質餘額，並填寫當期收支事件。
     - **儲存同步**：完成盤點後儲存，總覽與各洞察分頁即時更新，無須手動重整。
  2. **8 大瀏覽分頁 100% 唯讀檢驗 (Read-Only Insights)**：
     - **銀行餘額**：純瀏覽總餘額折線、實際 vs 理論偏離洞察、防跳票紅燈與閒置資金水位；**無**原地行內修改 `<input>`、**無**一鍵平帳按鈕、**無**跨行調撥彈窗（ADR-014）。
     - **信用卡費**：純瀏覽 12 個月疊加趨勢、扣除大額常態均值、高額警戒線；**無**原地標記扣款失敗/重試等破壞性按鈕。
     - **分期付款**：純瀏覽 12 個月退坡折線與自動期數進度；期數依起算年月自動推進，**無**手動 `+1 期` 按鈕。
     - **固定費用**：純瀏覽三線趨勢與剛性/浮動清單；**無**原地修改金額或切換已繳按鈕。
     - **台股部位**：純瀏覽持股總市值、損益與交割銀行現金池安全比例；**無**偽券商賣出平倉功能。
  3. **規則與名冊維護管理 (Master & Settings)**：
     - **收支規則 (#tab-rules)**：新增、修改常態收入規則 (`inflows`) 與固定費用規則 (`bills` 剛性/浮動分類、單雙月設定)。
     - **設定 (#tab-settings)**：維護銀行名冊、信用卡名冊、證券交割戶現金池綁定、防禦最低保留金設定、帳本 Profile 管理與資料備份/匯入/重設。

### 維度 5：跨分頁數學恆等式稽核 (Cross-Tab Math Invariants)
- **測試目標**：以嚴格的數學恆等式斷言，確保所有分頁的數據完全自洽，無任何四捨五入落差或加總遺漏。
- **數學恆等式檢驗表**：
  1. `總覽頁：總資產 (Total Assets)` === `銀行餘額頁：所有銀行餘額總和` + `台股部位頁：股票總市值`
  2. `總覽頁：總淨資產 (Net Worth)` === `總資產` - `未繳負債總額 (當期信用卡待繳 + 分期剩餘未繳)`
  3. `總覽頁右卡：總支出 (Total Outflow)` === `剛性固定負擔 (Fixed Bills)` + `浮動生活帳單 (Card Bills)` + `當期變動消費 (Transactions)`
  4. `總覽頁右卡：本月現金流餘裕 (Surplus)` === `常態收入 (Inflows)` - `總支出 (Total Outflow)`
  5. `導覽列紅點待辦徽章 (Badges)`：
     - `badgeBanks` === 銀行餘額不足扣款之帳戶數
     - `badgeCards` === 本月待繳之信用卡張數
     - `badgeBills` === 本月待繳之固定費用筆數

### 維度 6：RWD 響應式與視覺溢出檢查 (1280px 桌機 + 390px 手機)
- **測試目標**：驗證在不同解析度與裝置視窗下之排版美觀、可讀性與無溢出。
- **檢驗視窗**：
  - **Desktop**：`1280 x 800`（標準筆電與桌面瀏覽器）
  - **Mobile**：`390 x 844`（主流旗艦手機尺寸，如 iPhone 14/15/16）
- **檢驗項目與斷言準則**：
  - [ ] **水平捲軸溢出斷言**：在任何分頁下，`document.documentElement.scrollWidth` 必須等於 `window.innerWidth`（不產生意外水平滾動條）。
  - [ ] **Hero KPI 大字排版**：三欄 KPI 卡片文字在手機視窗下自適應縮放，無文字重疊、被換行破裂或省略號異常截斷。
  - [ ] **按鈕可點擊熱區**：手機視窗下按鈕熱區至少達到 `40px x 40px`，單手操作時無誤觸風險。
  - [ ] **表格卡片響應降級**：桌面表格在手機寬度下平滑切換為垂直卡片堆疊或支援水平滑動容器，不破壞全頁外框。

## 3. 執行標準作業程序 (Execution SOP)

1. **自動化驗證執行**：
   - 針對主力程式 `pocketmoney.html` 執行自動化測試腳本。
   - 每次重大功能合併或交付前，必須執行 `python pocketmoney/lint_ui.py` 確保零違規。
2. **全頁長截圖留存與審查**：
   - 截圖儲存於 `pocketmoney/logs/` 目錄。
   - 檔名規範：`<viewport>_<state>_<tab>.png`。
   - 透過視覺檢視覆蓋自頁首至頁尾，逐張檢查渲染完整性與視覺層級。
3. **報告產出**：
   - 產出詳細測試報告存入 `pocketmoney/logs/` 目錄，留存於專案供追溯。
