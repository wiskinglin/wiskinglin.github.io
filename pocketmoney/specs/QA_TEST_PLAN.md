# PocketMoney 全產品地毯式找碴與自動化驗收測試計畫書 (QA_TEST_PLAN.md)

> **本文件是 PocketMoney 產品驗收之最高品質標準與自動化回歸測試準則。**
> 任何功能合併至主力雛型 `pocketmoney.html` 或驗收原型（如 `F15-integrated-dashboard`）前，必須由獨立的 **QA Inspector** 依據本測試計畫書逐項執行嚴格檢驗，不得省略任何維度。

---

## 1. 測試目標與哲學

1. **Adversarial Mindset (找碴哲學)**：
   - 測試的目標不是「證明程式可以跑」，而是「以最刁鑽、最嚴苛的使用者角度，把潛藏的視覺破版、互動失效、計算矛盾、狀態殘留全部挖出來」。
2. **多模態全頁視覺守門 (Vision QA)**：
   - 杜絕僅靠程式碼靜態檢查或首屏截圖。必須使用 Playwright 截取全頁長截圖 (`full_page=True`)，覆蓋自頁首至頁尾，並透過視覺辨識逐張檢查渲染完整性。
3. **零容忍原則 (Zero-Tolerance Gate)**：
   - 0 JS Error / 0 Unhandled Rejection
   - 0 `NaN`、`undefined`、`null`、`Infinity%`、`-0` 或異常負數小數
   - 0 跨分頁數據矛盾
   - 0 DOM 外漏與全螢幕滿版破格
   - 100% 符合 `UI_VOCABULARY.md` 與 `UXD.md` 零 AI Slop 鐵律

## 2. 六大維度地毯式測試矩陣

### 維度 1：8 大分頁逐頁切換與 DOM 隔離檢查 (Tab Navigation & DOM Leak Audit)
- **測試目標**：確保 8 大核心分頁互相獨立，切換分頁時絕對不發生元件外漏、樣式破裂或標題狀態覆蓋。
- **涵蓋分頁**：
  1. `總覽 (tab-dashboard)`
  2. `銀行餘額 (tab-banks)`
  3. `台股部位 (tab-stocks)`
  4. `信用卡費 (tab-cards)`
  5. `分期付款 (tab-installments)`
  6. `固定費用 (tab-bills)`
  7. `收支規則 (tab-rules)`
  8. `設定 (tab-settings)`
- **檢驗項目與斷言準則**：
  - [ ] **DOM 隔離檢驗**：非當前作用中分頁（包含 `.hidden` 類別）其下任何卡片或圖表容器，其 `offsetParent` 必須為 `null`，且絕對不得渲染在當前可見畫面上。
  - [ ] **全頁長截圖審查**：切換至每一分頁皆需截取 `full_page=True` 圖片，檢查頁面最下方是否漏出其他分頁（如 `#tab-banks` 圖表漏在總覽底部、脫離 `<main>` 容器寬度變全螢幕）。
  - [ ] **頂部大標題一致性**：在切換各分頁（如切換至 `台股部位`、`設定`）後再點回 `總覽`，頂部大標題與 `<title>` 必須保持為規範字串，嚴禁被覆蓋為殘留字串或空白。
  - [ ] **視圖切換與收納按鈕響應**：
    - 銀行分頁：「卡片網格 / 緊湊表格」切換按鈕點擊後表格/卡片即時切換且無破版。
    - 信用卡分頁：「依卡片顯示 / 依扣款銀行歸戶」切換、以及「無消費信用卡收納/展開」點擊正常，收納項目折疊無留白破版。

### 維度 2：4 種資料生命周期狀態切換 (Data Lifecycle Audit)
- **測試目標**：驗證系統在無資料、載入示範資料、切換官方情境、以及完全清空後的所有狀態表現。
- **涵蓋狀態**：
  1. **狀態 A：初次開箱純淨 0 資料 (Empty State)**
     - 檢查項目：所有 8 個分頁無任何 `NaN`、`undefined`、`null`、`Infinity%`、`-0`。
     - Chart.js 刻度防呆：Y 軸座標絕對不得出現 `-0.2, -0.4, -0.8, -1` 等負數小數刻度。
     - 警報防呆：常態收入與支出為 0 時，嚴禁跳出「入不敷出赤字紅字警告」或「餘額不足」紅字。
     - 空狀態友善引導：各分頁優雅顯示「尚無帳戶/資料」提示與新增按鈕。
  2. **狀態 B：匯入 `test_demo_h2.json`（或點擊載入半年展示）**
     - 檢查項目：點擊匯入或載入後，所有 8 個分頁之數值、卡片與趨勢圖表必須「即時重繪 (Re-render)」，嚴禁需要重新整理 (F5) 才能看見。
  3. **狀態 C：相容性情境資料庫切換 (Official Scenarios DB)**
     - 依序匯入 3 份官方情境資料庫：
       - `pocketmoney/database/scenario_1_junior_installments.json`（初級大人・分期生活族）
       - `pocketmoney/database/scenario_2_sandwich_mortgage.json`（少子化勇者・三明治雙薪房貸族）
       - `pocketmoney/database/scenario_3_stock_investor.json`（高級大人・存股領息置產族）
     - 檢查項目：歷史卡費 `records` 跨月份相容性、分期總期數與剩餘期數、固定費用頻率（雙月/單月）、股票損益計算等，絕無卡費歸零或趨勢圖破裂。
  4. **狀態 D：完全清空重設 (Factory Reset)**
     - 檢查項目：於設定頁執行「完全清空重設」後，系統必須 100% 恢復至狀態 A 純淨狀態。
     - 殘留檢驗：圖表線條是否歸零、導覽列待辦紅點數字徽章（`badgeBanks`, `badgeCards`, `badgeBills`）是否即時清空為 0/隱藏、無殘留篩選或選取狀態。

### 維度 3：時間控制器與跨月切換交互測試 (Temporal Controller Audit)
- **測試目標**：驗證時間軸控制器在歷史、當前與未來月份切換時，所有分頁與模組的動態計算準確度與狀態一致性。
- **操作序列**：載入資料後，連續點擊 `前月 (<)` 3 次 ➔ `次月 (>)` 6 次 ➔ `指定日期選擇器` ➔ `回到今天 (↻)`。
- **檢驗項目與斷言準則**：
  - [ ] **全分頁響應檢驗**：在「銀行餘額」、「信用卡費」、「分期付款」、「固定費用」分頁點擊前後月切換時，該分頁內容與金額必須連動更新至該月份狀態。
  - [ ] **過去月份結清一致性 (Past Month Consistency)**：
    - 切換至歷史月份（如 2 個月前），信用卡若已繳款完成，在信用卡分頁應顯示「已扣款/已結清」，總覽頁待繳卡費應為 0。
    - 嚴禁出現「總覽頁顯示待扣 0，點進固定費用或信用卡分頁卻顯示紅色待繳未扣」的跨分頁矛盾現象。
  - [ ] **未來月份預估一致性 (Future Month Estimation)**：
    - 切換至未來月份（如次月、後月），尚未發生實際刷卡帳單時，總覽頁預估之浮動/分期支出必須與分期付款頁/信用卡頁之排程試算金額吻合。
  - [ ] **登記帳單抽屜跨月互動**：
    - 在不同月份打開「登記本期帳單」抽屜，輸入金額並儲存後，該月份的信用卡卡片、總覽支出卡與時間軸圖表必須即刻同步更新。

### 維度 4：CRUD 互動與彈窗/抽屜全流程測試 (Interactive CRUD & Modal Audit)
- **測試目標**：針對各模組之新增、行內編輯、刪除與特定金融業務動作進行全流程點擊驗證。
- **檢驗項目**：
  1. **銀行帳戶 (Banks)**：
     - 新增銀行：表單驗證、新增後即時出現在卡片與清單、總資產同步增加。
     - 行內編輯餘額：點擊金額原地修改，按 Enter/失焦即時儲存並重繪 KPI。
     - 刪除銀行：關聯警告防呆、確認後扣減總資產。
     - 跨行調撥：調撥彈窗操作、來源扣款、目標入帳、手續費處理。
  2. **信用卡 (Credit Cards)**：
     - 新增卡片：綁定扣款銀行、結帳日與扣款日設定。
     - 登記帳單：打開抽屜修改當期應繳金額並儲存，狀態自動切換為待扣款。
     - 單筆大額消費 (`> $5,000`)：新增與刪除大額消費，卡片總額即時連動。
     - 標記扣款失敗/重試：手動切換扣款狀態，觸發相應警示或重算。
  3. **分期付款 (Installments)**：
     - 新增分期：測試「填寫起算年月」與「不填起算年月（預設當月）」之排程計算。
     - 手動 `+1 期`：點擊按鈕後已繳期數加 1、剩餘金額即時減少。
     - 編輯與刪除分期：修改期數或金額、刪除後總負擔即時扣除。
  4. **固定費用 (Bills)**：
     - 新增固定費用：測試「銀行直接扣款 (`bank_direct`)」vs「信用卡代繳 (`card_auto`)」、「每月」vs「雙月（奇數月/偶數月）」。
     - 行內修改金額：修改後總支出與現金流餘裕即刻重算。
     - 狀態切換：切換「已繳」、「待繳」、「略過」，確認總覽待繳金額連動。
  5. **收支規則 (Rules)**：
     - 新增常態收入 (`inflows`)：薪資、租金或被動收入設定。
     - 修改規則金額/撥薪日：修改後總覽頁「常態收入」與「本月現金流餘裕」必須即時同步變更。
  6. **台股部位 (Stocks)**：
     - 新增持股：股票代號、名稱、股數、買入均價、現價。
     - 行內修改現價/股數：市值即時重算，總覽頁總資產連動。
     - 配息入帳：輸入股利金額與入帳銀行，銀行餘額即時增加並記錄交易。
     - 平倉賣出：輸入賣出價格與股數，試算損益並將資金結轉入帳戶。

### 維度 5：跨分頁數學恆等式稽核 (Cross-Tab Math Invariants)
- **測試目標**：以嚴格的數學恆等式斷言，確保所有分頁的數據完全自洽，無任何四捨五入落差或加總遺漏。
- **數學恆等式檢驗表**：
  1. `總覽頁：總資產 (Total Assets)` === `銀行餘額頁：所有銀行餘額總和` + `台股部位頁：股票總市值`
  2. `總覽頁：總淨資產 (Net Worth)` === `總資產` - `未繳負債總額 (當期信用卡待繳 + 分期剩餘未繳)`
  3. `總覽頁右卡：總支出 (Total Outflow)` === `剛性固定負擔 (Fixed Bills)` + `浮動生活帳單 (Card Bills)` + `當期變動消費 (Transactions)`
  4. `總覽頁右卡：本月現金流餘裕 (Surplus)` === `常態收入 (Inflows)` - `總支出 (Total Outflow)`
  5. `導覽列紅點待辦徽章 (Badges)`：
     - `badgeBanks` === 銀行餘額不足扣款之帳戶數
     - `badgeCards` === 本月待繳之信用卡張數
     - `badgeBills` === 本月待繳之固定費用筆數

### 維度 6：RWD 響應式與視覺溢出檢查 (1280px 桌機 + 390px 手機)
- **測試目標**：驗證在不同解析度與裝置視窗下之排版美觀、可讀性與無溢出。
- **檢驗視窗**：
  - **Desktop**：`1280 x 800`（標準筆電與桌面瀏覽器）
  - **Mobile**：`390 x 844`（主流旗艦手機尺寸，如 iPhone 14/15/16）
- **檢驗項目與斷言準則**：
  - [ ] **水平捲軸溢出斷言**：在任何分頁下，`document.documentElement.scrollWidth` 必須等於 `window.innerWidth`（不產生意外水平滾動條）。
  - [ ] **Hero KPI 大字排版**：三欄 KPI 卡片文字在手機視窗下自適應縮放，無文字重疊、被換行破裂或省略號異常截斷。
  - [ ] **按鈕可點擊熱區**：手機視窗下按鈕熱區至少達到 `40px x 40px`，單手操作時無誤觸風險。
  - [ ] **表格卡片響應降級**：桌面表格在手機寬度下平滑切換為垂直卡片堆疊或支援水平滑動容器，不破壞全頁外框。
